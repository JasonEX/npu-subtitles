# 实时字幕：来源账本、句子归属与播放期限

本文定义识别账本、句子组装、翻译预算和字幕显示的运行约束。

## 目标与约束

正常打开视频后，从当前播放位置持续识别、分句、翻译、显示；允许默认 8 秒的自动预读。所有神经推理只使用本地 NPU，设备不满足时明确失败，不回退 CPU。mpv 和 MPC-HC 使用同一字幕管线。参考字幕不进入运行输入，不使用片名、人物或台词纠正规则，不新增单元测试。

结构优化要同时满足内容完整、时间可解释、内存有界。不能只让最终全文更正确，却在观影时漏句；不能只保住旧卡，却把已经过时的字幕排队显示；也不能把已显示版本稳定误当成识别正确。

## 为什么需要更换职责划分

三部电影九场景的前一阶段暴露了两个可定位的结构问题：

- 新窗口在共享音频中恢复了八次 `Yo/yo`，旧窗口没有。单锚拼接选择较晚的共同词，将整段锚前文字交给旧窗口，导致新识别内容无从补回。时间约束的 token 匹配本身并不能解决“谁有权修改重叠区间”。
- 一张已经译好的字幕，其末词与时间持续稳定。后续音频的新词让模型重新安排标点，显示准备层因此撤销了旧卡；再提交时已超过原截止时间。问题发生在转写修订权限越过了字幕确认边界，延长超时只能掩盖它。

因此不再把“窗口文本拼接得像一句话”作为 ASR 的完成条件，也不让显示层通过全文字符串差异重新猜测字幕来源。

## 数据流与唯一职责

```text
播放器快照 / epoch
        ↓
有界音频读取 ── 原始样本位置是唯一时间轴
        ↓
NPU 窗口识别 → WindowObservation（证据，可更新）
        ↓
AcousticTranscriptLedger（已封存前缀 + 可修订尾部）
        ↓ TranscriptRevision
SentenceAssembler（草稿 → 认领已封存词 → 确认字幕段）
        ↓ CommittedSegment
NPU 翻译（固定文字快照 → 同版本中英配对）
        ↓ BilingualReady
PresentationController（准入、阅读、替换、退休）
        ↓
mpv / MPC-HC 显示适配
```

窗口识别层只报告音频证据；账本负责合并不同观察与管理修订权限；组句层负责每个词属于哪张字幕；翻译层不改变英文来源；显示层只执行生命周期。模型窗口结束、逻辑缓存封存、自然句末、字幕退出是四件不同的事。

## 三个前沿

设 `A = encoded_until`，表示已处理到的音频位置；`S = sealed_until`，表示识别层承诺不再修改的位置；`C` 表示字幕已经认领的来源末端。

始终维持：

```text
C <= S <= A <= 当前播放位置 + 允许的预读
```

`S` 只前进，不能因新的窗口而倒退。“封存”是版本承诺，不能解释为模型保证正确。只要仍在 `S` 之后，补词、改词、撤词都属于正常识别修订；一旦越过 `S`，后来修订应记录为合同违例或错过确认机会，不能偷偷改写已准备字幕。

## 窗口观察与识别账本

每个 `WindowObservation` 至少记录 epoch、物理窗口身份、真正推进的观察版本、覆盖音频范围、有效音频终点，以及 CTC token/词的原音频位置、blank 与置信度。同一个窗口的新结果替换该窗口的观察；活动通知和同音频重复计算不能算额外支持。

账本维护有界的完整候选路径。时间约束的一对一匹配用于辨别同一次发音，不能将匹配点之前的整个共享区永久交给旧窗口。不同词形是候选路径替换；旧侧为空、新侧有词也属于同一类路径竞争。一次发音只能选择一条路径，不能把两边冲突的词机械叠加。

候选的持续性、真实上下文覆盖及置信度用于选择和封存。没有可靠匹配时，先保留明确的不确定区间；达到音频保留或发布预算时，确定性选择一个完整候选并标记 `sealed_uncertain`。这个选择可能出错，但不能无限等待或用时间中点盲切两份文本再拼接。

窗口左缘缺少早先上下文，不能把“新窗口没有说出某词”直接当成该词不存在的证据。边界处保留有限的既有词证据，结合有序邻词的共同时间漂移辨认同一次发音；这只用于核对已经确认的出现及被窗口截断的词，不决定整个可修订区归旧。新窗口在旧空白中恢复的完整词路径仍可进入可修订尾部。词身份使用原音频位置、顺序与词形，tokenizer 的分段与标点变化不应自行创建第二次发音。

每个词出现具有稳定 `occurrence_id`。连续两次说相同的词是两个不同出现；标点不能作为出现身份。已封存词的文字、身份和来源跨度不可变，可修订尾部保留完整快照。`TranscriptRevision` 同时携带 `revision_from`、已封存前沿、不确定区间和路径来源，使每次补词、替换、删除都有明确归因。

身份合同不等于声学对齐正确。CTC emission 时间仍是近似证据；两个窗口可能将同一段声音拆成不同数量的词，且落在封存边界两侧。正式实播已经发现 `out of` 与另一个窗口的 `outside` 误接，以及完整 `patching` 被新窗口内部 token `atch` 替换的反例：没有违反 ID 唯一或前沿单调，却仍损害内容。此类路径选择错误必须计入文字差错并保留原始证据，不能被“合同零违例”掩盖，也不能用删除某个台词词组修饰结果。后续应在账本内统一处理整词完整性与跨边界候选的整体替换关系，不能把纠错职责移到组句或显示层。

模型仍采用现有静态 NPU 图。账本保存有限窗口的 token/词摘要，不保存整片 logits；逻辑文字历史受容量约束。容量封存可以结束日志中的上下文快照，但未完成的字幕草稿要跨该边界延续，不能把缓存容量当成句末。

## 整词证据与局部候选替换

词边界修复继续属于识别账本。窗口观察保存实际 tokenizer pieces、词首标记、词尾证据及原始 token 范围；不能仅凭解码后的字符串判断一个词是否完整。缺少词首标记本身不是删除依据，也不能据此猜出缺失前缀。

若新窗口的首个词只是旧完整词的内部 token 子路径，必须同时核对原 token 顺序、原音频位置，以及旧完整候选已有的可靠观察。证据成立时沿用旧完整词及其身份、时间和真实支持；内部片段不能为完整词增加一张支持票。不增加修订或保留时间来等待补词。

不同词组的替换必须比较两个真实窗口中的原始候选路径，不能用账本内来自不同窗口的邻词拼成一个假旧视角。相邻有序对应词界定局部候选范围，音频位置和邻词的一致偏移约束对应关系。旧范围为空而新范围有词，属于新增正证据；双方都有候选且占用同一发音位置时，才判断替换。属于同一竞争候选块的词必须整体择一，不能留下半条新路径接到旧路径上。

已经确认的词不可撤回；确认边界附近的冲突需要保留选择依据。其他可修订范围仍允许完整的新候选替换旧候选。真实连续重复依靠各自的出现顺序和声学位置区分，不能使用相邻去重或电影台词规则。邻词只能佐证局部对应，不能把它之前的整个共享区划归旧窗口，也不能用时间包络填平旧候选中的空白。

整词证据、候选择一和确认时间分别审计。相同原始观察回放要比较首次确认位置、前沿推进、共同词及单侧新增／丢失；实际播放器还要另查句子提交和双语出现时间。词形修复不保证译文正确，确认时间不晚也不保证分句和上屏不晚。

## 组句与词归属

组句器可以读取可修订尾部作为草稿，但只能认领已封存的连续词出现。标点、CTC 词间距、VAD 停顿和阅读长度均为草稿边界证据，由同一处策略统一决策。

每个已封存词必须处于以下一种状态：待分配、属于一张明确的字幕段、因截止或其他明确原因放弃。不能因为 `consumed` 词数移动或字符串匹配偏移而无记录消失。

物理换窗不结束草稿。短问句不能仅因为词少被丢弃；在可读长度预算内的完整语句保留为一段。过长语句在已经确认的从句、停顿或有界长度点分段，并明确标记续句。模型未识别出的内容不能由组句器编造。

阅读容量已满时，若真实后续词已经被观察到且位于当前段之后，就可以启动原有阅读分句选择，不必再等那个后续词也封存。只认领已封存词的限制不变；没有后词、尚未满容量、或后词时段仍与当前段重叠时，不能据此强切。这样避免一次源文纠错减少了一个错误词后，无端多等一轮“超过容量”的确认事件。

确认时生成 `CommittedSegment`：稳定身份、认领词出现、来源区间、句界理由、文字版本和绝对期限一起固定。后续新词只进入尚未认领的来源区域，不能因句号变化重新打开旧字幕。

## 字幕状态与修改权限

| 状态 | 可变部分 | 固定部分 |
| --- | --- | --- |
| 识别可修订尾部 | 未封存区内的词、候选标点与路径 | 已封存词及其身份、时间 |
| SentenceDraft | 未认领词的组合、候选句界 | 其他字幕已经认领的来源 |
| CommittedSegment | 翻译任务状态 | 文字快照、词归属、来源、句界、期限 |
| TranslationPending | 是否完成、取消或超时 | 输入版本与所属字幕 |
| BilingualReady | 按播放位置等待显示 | 成对中英文及原期限 |
| Displayed | 正常替换、过期或 epoch 失效 | 当前文字与阅读期限 |
| Retired | 仅保留诊断记录 | 不得重新入队 |

当前实现只在字幕段确认后翻译。未来若增加推测翻译，只能先作为草稿缓存，不能提前占有显示队列，更不能先撤掉可用双语字幕，再等待替代翻译。

翻译回包必须匹配字幕身份及输入版本；翻译失败、超时、迟到不改变来源区间，不刷新期限。已确认段正常只因 seek、音轨或 epoch 改变而失效，或按期限退休。显示层不再对新的 ASR 全文执行字符串修订。

当前实现遇到前沿倒退、封存前缀被改写或词身份冲突时明确报错并结束该次播放管线，由现有清理逻辑回收播放器和工作进程。不能永久空屏却继续假装字幕正常运行，也不通过 CPU 推理或静默重置隐藏合同错误。

## 一份端到端时间预算

确认前沿、分句、翻译和显示共同消耗预读预算。每张卡至少记录来源起止、假设可用、来源封存、句子确认、翻译提交/就绪、显示调用完成和退出时刻，并区分媒体时间与墙上时间。

前沿不能混用：`C <= S` 决定哪些词可以被字幕认领；已经确认的句末需要多少已观察右上下文，应看 `A` 和真实观察证据，不必再等下一句话封存。没有后词时的空白确认则仍需封存的无词区间或独立声学证据，不能只因 `A` 前进就宣称静音。

草稿的最晚提交时刻与翻译最终准入时刻分别定义。前者要从后者扣除翻译保留时间、当前工作任务的占用和调度余量，并由播放循环持续推进；不能等到翻译已经不可能及时完成时才释放草稿。双语卡只有完成配对后才进入正常显示资格；翻译失败或明确无法及时完成时，才以同一来源及原期限进入英文回退状态。

默认约四秒可修订尾部、六秒保留预算，均在实际推进解码时判定，不是六秒墙钟硬实时保证。预读八秒也是读取上限，并不代表已获得八秒计算余量；还要扣除句子长度、ASR 发布步长、模型任务占用和翻译时间。NPU 内核不能由协作式截止检查即时中断，因此必须记录不可行与迟到，而不能宣称所有情况都能近零延迟。

期限从来源时间一次确定；等待识别、翻译或前一张字幕都不能重新起算。超过最晚显示机会时直接退休并保留原因，不在后续安静片段逐条补播。预算不足应明确表现为迟到或遗漏，不能隐藏为更长队列。

暂停时媒体时间不前进，读取在预读边界停止，墙上时间仍可用于工作任务超时。恢复继续同一 epoch。拖动生成新 epoch，音频、识别账本、草稿、翻译回包和显示队列全部隔离旧状态。

## 当前代码边界

| 模块 | 当前职责 |
| --- | --- |
| `npu_subtitles/asr/granite.py` | PCM 与物理窗口、特征、NPU 推理、原始窗口观察；不再直接拼接跨窗文本 |
| `npu_subtitles/asr/transcript.py` | `WindowObservation`、有界候选路径、稳定词出现身份、封存前沿与边界证据 |
| `npu_subtitles/captions/sentences.py` | 只认领已封存词，维护跨窗口／容量的草稿，统一句界与阅读预算，产生不可变字幕段 |
| `npu_subtitles/captions/timing.py` | 来源时间排期；根据同一准备预算计算最晚提交时刻 |
| `CaptionPipeline` | 按来源合同选路；接收工作进程代价并统一计算翻译／调度预留，每帧推进草稿 |
| `PresentationController` | 消费固定字幕段与翻译快照，统一显示资格、阅读机会和退休；不修改 Granite 原文 |
| `npu_subtitles/app.py` | 播放时间线、串行 NPU 任务调度、真实工作状态反馈、播放接口与阶段日志 |

Moonshine 使用自己的观察时间与组句路径；运行时按来源协议选择处理方式，不把 Granite 的词时间假设套到 Moonshine。
